bough on AWAGY

bough, run through the two workloads of Are we actually GUI yet? on this Mac, next to the site’s own two Vizia apps, built and measured here the same way, and next to two frameworks the site does not register, zgx and BUI (Blender’s UI as a library), measured here with the same protocol. The site's own collection was on Linux at 144 Hz and cannot include bough, so its numbers appear only as context.

How this was measured

Machine
__MACHINE__. Other work was running; frame pacing is what the window server showed at the time.
Builds
The site’s Vizia apps at its main branch (apps/vizia, and apps/vizia-optimized with Vizia’s rayon feature), --release --locked, Rust 1.97.1, with the harness’s feature selection.
bough
comparisons/bough-awagy, written only with bough’s application surface: flow layout by cephal, div().scroll(..), text, button, image, text_input, routes as methods, Application::run.
Presents
MangoHud does not exist on macOS. An injected library records each frame handed to the window server: a Metal drawable taken (wgpu, GPUI, Skia), an OpenGL flush (egui’s glow), an IOSurface published (bough), a tile of a plain layer shown (zgx: -[CALayer setHidden:NO] on an IOSurface-backed layer), or a view drawn by displayIfNeeded (BUI’s CPU raster). The window and statistics are the site’s frames.py rules: anchored on a frame, gaps from the previous frame, the trailing silence counted, ceiling-index percentiles.
Input
The harness’s schedule as macOS events. The pointer is moved over the window and wheel and clicks are real pointer input, routed by the window server, as XTest’s are on Linux. Keys are posted to the app’s process only, so they can never land in another app. Each app was activated, and runs whose window became covered were rejected.
Memory and CPU
proc_pid_rusage: resident memory (the site’s RSS), plus macOS’s physical footprint, which also counts the GPU driver’s memory; CPU time inside the measured window.
